# Sync Vault 0.2.3 릴리즈 검증

2026년 11월 29일, Windows 11 x64와 Apple Silicon Mac에서 커밋 `b09c41ef01df17a68598ce823a224922368a928f`를 빌드했습니다. Windows 빌드 26300에서는 Node.js 26.13.0과 npm 11.20.0을 사용했습니다. M4의 격리된 macOS 26.6.2에서는 Node.js 24.21.0과 npm 11.19.0으로 의존성을 설치하고 앱을 빌드했습니다. 단위 시험의 임시 경로가 macOS 심볼릭 링크를 가리켜 첫 실행에서 실패했고, 실제 경로를 지정해 전체 검사를 통과했습니다. 이어서 시험 도우미가 임시 경로를 직접 정규화하도록 수정하고 양쪽 OS의 기본 설정에서 17개 시험이 모두 통과하는 것을 확인했습니다. 양쪽의 Electron 버전은 44.10.0이고 릴리즈 공개키의 SHA-256은 `2c80cb076ed390c044a0e54a5fb378482aa04b2ae2194aef354f4b09eb667709`입니다.

| --- | --- | --- |

| 설치 실패 복구 | 이전 앱과 설정 복원 | 이전 앱과 설정 복원 후 LaunchServices 실행과 종료 확인 |

게시 전 업데이트 시험은 GitHub의 메타데이터와 자산 응답을 후보 파일로 대체했습니다. 두 OS 모두 다운로드 취소·재시도, 전송 완료 후 교체·재시작, 기기 ID·등록 기기·수신 파일 보존을 확인했습니다. Windows EXE는 Authenticode 미서명이고 Mac 앱은 ad-hoc 서명입니다. Mac 앱은 Apple 공증을 받지 않았습니다.

0.2.2 시험 앱이 만든 로그인 키체인 항목에 0.2.3이 처음 접근할 때 macOS의 SecurityAgent 창이 떴습니다. 앱이 키체인 조회에서 승인을 기다리며 자동 기동 시험이 시간 초과된 것을 창 목록과 프로세스 표본으로 확인했습니다. 새 설치·동일 버전 재설치 시험은 임시 VM에서 이전 후보가 생성한 항목 한 개를 정리한 뒤 실제 로그인 키체인으로 통과했습니다. 자동 업데이트 E2E는 시험용 키체인을 사용했습니다.

## 기기 간 공유

공개 전 0.2.2 후보에서 Mac 원본 앱을 재시작한 후 Windows의 응답 대기 연결이 끊기자 5 GiB 수신 작업이 오류로 종료됐습니다. 0.2.3에서는 이 연결의 시간 초과·종료를 식별해 재연결 대기로 전환합니다. 상대가 요청을 거절한 경우는 별도로 처리합니다. 이 차이를 단위 시험에 추가했고 미공개 0.2.2 초안과 태그를 정리했습니다.

물리 Windows PC와 M4 호스트가 같은 LAN에서 서로를 발견했습니다. 각 방향으로 한글 메시지 100건, 파일 100개와 빈 폴더를 전송했습니다. 메시지 왕복 p95는 Windows 송신 12.4 ms, Mac 송신 12.5 ms였습니다.

두 OS의 정식 설치본 간 시험은 격리 Mac에서 연결을 시작하고 Mac 호스트의 루프백으로 Windows 앱의 두 포트를 전달했습니다. 코드 확인과 등록, 양방향 클립보드·파일 가져오기, 잠금·해제, 수신 폴더 단절 후 재시도, HFS+ 공간 부족 후 복구와 해시 일치를 확인했습니다. 방향별 20회 측정한 목록 조회 p95는 기록 41 / 91 ms, 1,000개 파일 중 첫 페이지 60개는 49 / 95 ms였습니다. 각 방향의 기준은 1초입니다.

Windows → Mac과 Mac → Windows 양쪽에서 5,368,709,120바이트를 가져왔습니다. 각 방향에서 원본 앱을 2,684,354,560바이트 시점에 재시작한 뒤 같은 수신 작업이 자동으로 완료됐습니다. 수신 파일과 원본을 별도로 읽은 SHA-256은 모두 `dc15110a74da628b09e829f66ba5cf39e64579b2c53cdd31c0f327480e1a406c`였습니다.

각 OS에서 설치본 두 개의 창을 숨기고 20분간 5초마다 측정했습니다. 네 프로필 모두 241개 표본에서 창이 숨겨져 있었습니다.

| 설치 환경 | 프로필별 평균 CPU | 처음과 마지막 1분의 메모리 중앙값 차이 |
| --- | --- | --- |
| Windows x64 | 0.79% / 0.76% | +1.8 / +2.2 MiB |
| macOS arm64 | 0.41% / 0.41% | −29.6 / −30.0 MiB |

기준은 프로필별 평균 CPU 2% 이하, 메모리 증가 32 MiB 이하입니다.

## 정리

Windows 시험 설치본은 자체 제거 프로그램으로 제거했습니다. 시험 설치 등록과 바로가기, 포트 포워딩과 로컬 릴리즈 임시 폴더가 없음을 확인했습니다. M4에서는 게스트의 시험 경로 설정을 해제하고 VM을 종료한 뒤 가상 디스크, 의존성 캐시, 작업 사본과 빌드 파일을 포함한 이번 원격 작업 폴더를 삭제했습니다. 작업 경로·프로세스·마운트를 다시 조회해 정리를 확인했습니다.
