# Sync Vault 0.2.1 릴리즈 검증

Windows x64와 Apple Silicon Mac에서 커밋 `56f7af82d55972079a406adc52c57290af9f402d`를 각각 빌드했습니다. Windows 11 빌드 26300에서는 Node.js 26.13.0과 npm 11.20.0을 사용했고, M4 빌드 호스트(macOS 27.2.1)에서는 Node.js 24.21.0과 npm 11.19.0을 사용했습니다. 두 패키지의 Electron 버전은 44.10.0입니다.

## 설치와 업데이트

| 검사 | Windows | macOS |
| --- | --- | --- |
| 빌드 전 검사 | 타입 검사와 단위 시험 13개 통과 | 타입 검사와 단위 시험 13개 통과 |
| 설치와 첫 실행 | NSIS 설치 후 설치 경로의 EXE로 실행 | DMG 체크섬, 번들 서명, 설치본 복사 검증. M4의 격리된 macOS 26.6.2에서 LaunchServices와 실제 로그인 키체인으로 두 차례 숨김 기동하고 같은 기기 ID와 서비스 준비 확인 |
| 트레이·메뉴 막대 | 로그인 인수로 숨김 기동, 30회 닫기·다시 열기, 렌더러 복구, 종료 후 포트 해제 | 같은 시험 30회 통과. DMG의 앱을 삭제하고 다시 설치한 뒤 기기 ID와 설정 보존 |
| 앱 정보 | GitHub 조회·오류 복구, 자동 확인 설정과 마지막 확인 시각 보존 | 같은 시나리오 통과 |
| 서명된 ZIP으로 교체 | 시험 버전 0.0.9에서 실제 0.2.1로 교체. 다운로드 취소 직후 임시 파일 제거, 재다운로드, 진행 중인 전송 완료 후 재시작, 기기 ID·등록·수신 파일 보존 확인 | 같은 시나리오 통과. macOS가 정규화한 수신 경로와 저장 전후의 경로를 비교하도록 시험을 수정하고 다시 통과 |
| 시작 실패 복구 | 이전 프로그램과 설정 복구 | 이전 프로그램과 설정 복구 후 LaunchServices 기동과 종료 확인 |

0.0.9는 같은 업데이트 코드를 낮은 버전으로 패키징한 시험용 앱입니다. 기존 0.1.1 사용자는 이 릴리즈의 설치본으로 한 번 직접 교체합니다. Windows EXE는 Authenticode 미서명이고, Mac 앱은 ad-hoc 서명이며 Apple 공증은 받지 않았습니다. 앱 내 업데이트에 쓰는 Ed25519 공개키는 두 빌드에서 일치했습니다.

호스트 Mac에서 허용 폴더 밖 쓰기를 막은 실행은 화면 준비 중 시간 초과가 발생했습니다. 가상 Mac에서는 개발 시험이 `/var` 심볼릭 링크 아래에 프로필을 만들자 공유 폴더 검사가 기동을 중단했습니다. 시험기가 임시 폴더의 실제 경로를 사용하도록 수정한 뒤 개발용 전체 UI 시험이 통과했습니다. 위 macOS 설치 결과는 DMG에서 복사한 정식 앱으로 측정했습니다. 로그인 키체인 검사는 해당 가상 Mac의 일반 콘솔 세션에서, 나머지 자동 UI 시험은 시험용 키체인으로 실행했습니다.

## 공유와 성능

각 OS에서 독립 프로필 두 개로 등록 거절·취소·양쪽 코드 확인, 한글·서식·PNG 가져오기, 창을 닫은 상태의 파일·빈 폴더 전송, 수신 폴더 단절 후 재시도와 원본 보존을 확인했습니다. Mac에서는 네이티브 편집기에 서식을 붙여넣고, 가득 찬 HFS+ 시험 볼륨에서 공간 확보 후 수신과 해시 일치까지 확인했습니다.

| 측정 | Windows 두 프로필 | Mac 두 프로필 |
| --- | --- | --- |
| 기록 목록 p95, 방향별 20회 | 11 / 18 ms | 3 / 3 ms |
| 파일 1,000개 중 첫 페이지 60개 p95, 방향별 20회 | 24 / 26 ms | 10 / 11 ms |
| 5 GiB 전송 중 원본 앱 재시작 시 수신 바이트 | 2,688,548,864 | 2,696,937,472 |
| 창을 숨긴 20분 평균 CPU, 각 프로필 | 0.58% / 0.57% | 0.21% / 0.20% |
| 창을 숨긴 20분 메모리 변화, 각 프로필 | +6.2 / +7.2 MiB | −59.8 / −58.2 MiB |

두 환경에서 이어받은 5,368,709,120바이트 파일을 원본과 독립적으로 읽어 확인한 SHA-256은 `dc15110a74da628b09e829f66ba5cf39e64579b2c53cdd31c0f327480e1a406c`입니다. Windows 목록 측정은 같은 커밋의 개발 실행본, Mac 목록과 양쪽 5 GiB 측정은 설치본에서 실행했습니다.

물리 Windows와 M4 호스트 간 LAN에서는 양쪽이 상대를 탐색했습니다. 후보 소스의 전송 시험에서 각 방향으로 한글 메시지 100건, 파일 100개와 빈 폴더를 주고받았습니다. 메시지 왕복 p95는 Windows 송신 8.9 ms, Mac 송신 8.8 ms였습니다. 이 수치는 전송 계층의 왕복 시간입니다.

Windows와 가상 Mac의 **실제 설치본**을 연결한 시험에서는 코드 확인, 양방향 클립보드·폴더 가져오기, 잠금 중 접근 차단, 수신 폴더 복구와 등록 해제를 확인했습니다. Windows 시험 설치 경로에 대한 LAN 인바운드 직접 연결은 시간 초과됐습니다. 교차 설치 시험은 Mac이 연결을 시작하고 호스트의 루프백에서 두 앱 포트만 SSH로 전달하는 방식으로 실행했습니다. 두 방향의 목록 p95는 기록 34 / 87 ms, 파일 61 / 81 ms였습니다. Windows 원본 앱을 2,684,354,560바이트에서 재시작한 뒤 Mac이 5 GiB 전체를 이어받아 위 SHA-256과 일치했습니다. 20분 상주는 각 OS에서 별도로 측정했으며 프로필마다 241개 표본에서 창이 숨겨져 있었습니다.

## 작업 종료 후 확인

Mac에서 임시 경로 설정을 해제하고 가상 기기를 종료했습니다. `~/Workspace/personal/` 아래 이번 실행 폴더와 소켓 폴더를 삭제한 뒤 가상 디스크·캐시·작업 사본을 담았던 두 경로, 관련 프로세스·마운트·포워딩, `syncvaultqa` 계정이 없음을 확인했습니다. Windows에서는 시험용 NSIS 설치본을 자체 제거 프로그램으로 삭제한 뒤 관련 실행 프로세스·제거 등록·바로가기·QA 계정이 모두 0개임을 확인했습니다. 릴리즈 작업 폴더와 중단된 시험의 임시 프로필도 삭제했습니다.
