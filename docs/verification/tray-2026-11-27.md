- 양쪽 설치본에서 자동 발견과 등록, 양방향 동시 수동 파일 수신 승인·내용 확인을 통과했습니다. 양쪽 창을 닫고 Windows 전용 스테이션과 Mac 전용 pasteboard에 파일 두 개씩을 복사해 상대의 수신 경로와 원본 바이트를 확인했습니다. 시험용 확인 대화상자는 자동 응답했고 Mac의 Playwright 세션은 모의 키체인을 사용했습니다.

- Windows 소스 앱에서 로그인 인수로 숨김 시작, 30회 닫기·다시 실행, 렌더러 복구, 종료 후 포트 반환을 확인했습니다. 처음에는 충돌 전 Playwright 페이지 핸들을 다시 사용해 실패했고, 다시 로드한 렌더러에서 실제 기기 ID를 읽도록 검사를 고쳐 통과했습니다.

### 같은 LAN에서 0.1.1과 비교

첫 비교와 실행 순서를 바꾼 두 번째 비교 모두 Mac→Windows가 정식판의 80%에 미달했습니다. Windows의 기존 정식판 경로는 개인망 수신이 허용됐고 새 Dev 경로에는 차단 규칙이 있었습니다. 정식판도 새 QA 경로에 복사해 실행 파일 해시를 대조하니 두 시험 경로 모두 같은 수신 차단 조건이 됐습니다. 방화벽 규칙은 조회만 했습니다. [첫 비교](tray-2026-11-27/compare-34d53ca7.json) · [순서를 바꾼 비교](tray-2026-11-27/compare-dd33f275.json)

동일 조건 재시험 `31d1c310`에서 발견은 OS당·버전당 20회, 파일은 방향당·버전당 256MiB씩 3회 측정했습니다. 각 파일의 SHA-256이 일치했습니다. 앱에서 관찰한 요청 종류와 건수를 사용해 Windows→Mac은 직접 전송, Mac→Windows는 기존 연결의 응답 경로로 두 버전이 일치함을 확인했습니다.

## 전달본과 정리

시험 코드의 최종 커밋은 `e7f5092`입니다. Windows에서는 Dev 자체 제거 프로그램으로 QA 설치 앱을 제거했고, Mac에서는 읽기 전용 정식판 이미지를 분리한 뒤 이번 작업의 전용 디렉터리를 정리했습니다. 중간 후보와 0.1.2 시험 피드는 제거했습니다. GitHub에는 소스와 검증 기록을 반영하며 개발 설치본은 각 기기에 직접 전달했습니다.

남은 실사용 재시험을 위해 Windows의 `artifacts/qa-32cf546/`와 Mac의 `~/SyncVault-Dev-QA-32cf546/`에 최종 EXE·DMG를 각각 한 개씩 보관했습니다. 각 폴더에는 해시 명세도 있습니다. 재시험 완료 시 `node scripts/dev-delivery.mjs clean <installer.json>`으로 전달본을 확인한 뒤 삭제할 수 있습니다.
