# Sync Vault 데스크톱 검증

Windows 11 x64와 Apple Silicon Mac에서 같은 소스를 사용합니다. 릴리스 판정에는 설치한 두 앱이 필요합니다. 별도 프로필로 실행한 프로세스 수와 물리 기기 수를 각각 기록합니다.

[기능별 대응표](../tests/feature-coverage.json)에서 제품 동작별 테스트와 실기기 항목을 찾을 수 있습니다. `npm run check`는 제품 IPC 목록이 바뀌거나 연결된 시험 파일이 사라지면 실패합니다. 실행 결과는 후보별로 별도 기록합니다. 설치본 패키징과 배포 판정은 [릴리즈 절차](release.md)를 따릅니다.

## 실행 순서

| 명령 | 확인하는 동작 |
| --- | --- |
| `npm ci`, `npm run check` | 타입, 파일·크기 경계, TLS 등록·해제, 양방향 전송, 체크포인트, 상태 복원, 서명된 업데이트 |
| `npm run test:e2e` | 홈과 방에서 등록·거절·양쪽 코드 확인·선택 복사·폴더 가져오기·오류 복구·설정 초기화. 로그인 실행 인수로 숨김 시작, 30회 닫기·재실행, 감시 프로세스 재시작, 렌더러 충돌 복구, 종료·포트 반환 |
| `node tests/session-start.cjs` | 로그인 직후 화면이 잠겨 있거나 초기화 도중 잠금·해제가 바뀌는 순서를 재현합니다. 창 숨김과 실제 공유 조회 동작을 검사합니다. 이 시험은 OS 상태와 이벤트를 주입합니다. |
| `npm run dist:dev` | 현재 OS용 개발 앱과 EXE 또는 DMG, 같은 폴더의 `installer.json` 생성 |
| `npm run dev:delivery -- copy <installer.json> <새-전달-폴더>` | 설치 파일과 명세 복사, 복사 전후 SHA-256 대조. 다른 기기로 직접 복사한 경우 도착한 기기에서 `verify <installer.json>` 실행 |
| `node scripts/test-osclip.mjs` | Windows 전용 스테이션에서 한글·HTML·투명도, 민감 표시·일시 중지·잠금 플래그, 실제 Chromium 붙여넣기 확인. 다음 실기기 시험용 스테이션 도구도 생성 |
| `npm run test:e2e:desktop` | Windows 제어기에서 양쪽 앱을 실행합니다. 페어링, 클립보드 기록과 명시적 복사, 폴더 탐색·가져오기, 원본 변경·중복·디스크 부족·접근 해제와 목록 응답 시간을 검사합니다. 디스크 부족은 Mac의 별도 시험 볼륨을 사용합니다. |
| `npm run test:e2e:desktop -- --soak` | 양쪽 창을 숨기고 20분간 CPU와 메모리를 측정합니다. |
| `npm run test:e2e:desktop -- --large` | 5 GiB를 절반에서 중단한 후 앱을 재시작하고 끝까지 이어받습니다. |
| `node tests/native-tray.mjs` | Windows 알림 영역 또는 Mac 메뉴 막대의 실제 메뉴에서 공유 재개·중지·열기·종료. UI Automation 또는 macOS 손쉬운 사용 접근이 가능한 로그인 세션에서 실행 |
| `node tests/native-tray.mjs --menu-callbacks` | 같은 설치본의 메뉴 항목에 연결된 네 명령을 호출하고 상태·창·프로세스 결과를 확인합니다. OS가 아이콘 클릭을 전달했는지는 위의 실메뉴 시험에서 판정합니다. |
| `node tests/installed-channels.mjs <정식실행파일> <개발실행파일>` | 정식판과 개발판을 전용 프로필로 동시에 실행합니다. 초기 수신 경로와 공유 설정, 양방향 직접 등록 거절, 개발판 업데이트 차단, 정식판 재실행 후 기기 ID·설정 보존을 확인합니다. |
| `node tests/pull-upgrade.mjs <0.1.x-정식실행파일>` | 구버전에서 등록한 두 시험 프로필을 차례로 새 소스 빌드로 엽니다. 상대 버전 안내와 기기 ID·받은 자료 보존, 재등록 없는 전송을 검사합니다. 먼저 `npm run build`를 실행합니다. |
| `npm run test:perf` | 같은 가져오기 시험에서 양방향 목록 p95를 기록합니다. [성능 기준](performance.md) 참조 |

실기기 시험에서는 Windows의 `SYNC_VAULT_QA_EXE`에 설치한 Dev 실행 파일 경로를 지정합니다. `SYNC_VAULT_MAC_HOST`는 Mac SSH 별칭, `SYNC_VAULT_MAC_DIR`은 같은 시험 코드와 의존성이 있는 Mac 작업 폴더, `SYNC_VAULT_MAC_NODE`는 Node 실행 파일, `SYNC_VAULT_MAC_EXE`는 앱 내부의 `Contents/MacOS/Sync Vault Dev` 절대 경로입니다. Mac 호스트를 지정하지 않은 실행은 로컬의 격리된 두 프로필을 사용합니다. `SYNC_VAULT_QA_REPORT`를 지정하면 PNG와 결과 JSON이 해당 폴더에 생성됩니다.

양쪽에 별도 프로필과 시험용 클립보드를 만들고 Mac은 모의 키체인을 사용합니다. 잠금 이벤트 주입과 실제 사용자 세션의 잠금·재로그인은 결과를 따로 기록합니다. 보고서를 다시 만들려면 `node scripts/pull-report.mjs <기능-결과-폴더> <출력.html> <5GiB-results.json> <상주-results.json>`을 실행합니다. 별도로 확인한 결과는 문자열 배열 JSON을 마지막 인수로 전달해 보고서에 함께 담을 수 있습니다.

공존 시험에 `--login-item`을 붙이면 시험용 Dev 앱을 OS 로그인 항목에 등록한 뒤 해제하고 양쪽 상태를 조회합니다. 시작 시 이미 등록된 앱은 이 단계에서 중단합니다. 실제 재로그인 시험은 별도 계정에서 수행합니다.

## 0.1.x 자동 전송 회귀 및 별도 실기기 시험

다음 표는 기존 자동 전송 방식의 시험 기록과 실제 OS 조작이 필요한 시나리오입니다. 0.2 개발판의 가져오기 방식은 위 명령으로 검증합니다.

| 기능 | 실행과 판정 |
| --- | --- |
| 최초 설치와 공존 | 정식판의 기기 ID·피어·수신 경로·로그인 설정을 기록합니다. Dev 설치 후 별도 이름·아이콘·수신 폴더·등록 목록과 초기 일시 중지를 확인합니다. 정식판 주소로 직접 등록을 시도해 거부를 확인합니다. Dev만 제거하고 정식판을 열어 처음 기록 및 수신 파일 해시와 대조합니다. |
| 직접 실행과 자동 실행 | 직접 실행하면 창 하나가 열립니다. 자동 실행을 켠 전용 계정에서 로그아웃·로그인하고 OS 데스크톱 관찰을 시작 시점부터 기록합니다. 창이나 포커스 이동 없이 트레이에서 공유돼야 합니다. Mac은 Dock 표시도 확인합니다. 자동 실행 해제 후 다음 로그인에서 프로세스가 없는지 확인합니다. |
| 대기 요청과 알림 | 두 창을 닫고 새 기기 등록과 수동 수신을 각각 요청합니다. 알림은 요청당 한 번이며 클릭하면 그 요청이 있는 화면이 열립니다. 알림을 지운 뒤에는 트레이로 찾아갑니다. 알림 차단·집중 모드, 요청 취소·만료 뒤의 클릭과 동시 요청 두 건도 확인합니다. 승인 전에 최종 파일이 생기면 실패입니다. |
| 실제 클립보드 소비 | 한글·이모지·탭·표·링크를 브라우저 편집기에, 여러 파일을 Finder·탐색기에 붙여넣습니다. 화면의 모양과 파일별 해시를 확인합니다. 불투명·투명 픽셀, 다중 이미지, 0바이트와 빈 폴더, 최신 복사가 앞선 자동 파일 수신을 추월하는 경우를 양방향으로 봅니다. 설치된 Office 앱은 이름·버전과 결과를 별도 기록합니다. |
| 개인정보와 복구 | OS에서 실제로 잠그고 상대가 새 텍스트를 복사합니다. 잠금 중 자동 반영과 해제 후 이전 항목 전송은 0건이어야 합니다. 해제 뒤 새로운 복사 하나가 정확히 한 번 도착해야 합니다. 일시 중지·유형별 해제·민감 표시도 같은 순서로 봅니다. 수동 파일 전송의 정책은 별도로 확인합니다. |
| 네트워크 | 정상 LAN 발견, mDNS를 사용할 수 없을 때 같은 서브넷 UDP 발견, 수동 주소 등록, 한쪽 인바운드 제한을 확인합니다. 이름이 같은 두 기기는 인증서로 구분해야 합니다. 절전·복귀, IP 변경, 실제 Wi-Fi 재연결 뒤 재등록 없이 다음 복사와 전송에 성공해야 합니다. |
| 파일과 저장소 | 32MiB·100개·8,000개 경곗값, 이름 충돌과 유니코드 정규화, 거절·취소, 수신 경로 변경, 원본 삭제·변경, 외장 매체 분리·용량 부족을 검사합니다. 오류 시 완성본이 생기지 않고 재시도 후 기존 파일과 새 파일의 내용이 보존돼야 합니다. `node artifacts/test/large.cjs`는 11GiB 이상 여유 공간에서 5GiB 전송을 절반에서 끊고 다시 시작합니다. |
| 업데이트 | `npm run check`로 GitHub 정식 태그·플랫폼·서명·ZIP 해시와 취소·재시도를, `node tests/desktop.mjs`로 앱 정보 화면의 확인 시각과 자동 확인 설정을 검사합니다. `node tests/rollback.mjs`로 시작 실패 복구를 확인합니다. 공개 자산을 받는 설치본의 OS별 시험과 기존 0.1.1의 수동 전환은 [릴리즈 절차](release.md)에 기록합니다. |

## 결과와 정리

후보별로 실행 ID, 소스 커밋, 운영체제와 아키텍처, 실제 설치 파일 해시, 시험 코드 버전, 표본 수, 최초 실패, 수정과 재실행 결과를 적습니다. `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN`, `N/A`를 구분합니다. 실제 로그인·알림 클릭·Finder/탐색기 시험에는 관찰한 OS 세션과 결과가 필요합니다.

### 원격 작업 필수 정리

SSH로 빌드·시험·배포를 수행하는 작업자는 성공, 실패, 중단 여부와 관계없이 다음 절차를 지켜야 합니다.

이 프로젝트가 원격 Mac에 쓸 수 있는 경로는 `~/Workspace/personal/` 아래뿐입니다. 작업이 끝난 뒤에는 그 안의 Git 체크아웃만 보관할 수 있습니다. 임시 작업 디렉터리, 앱 프로필, `TMPDIR`, 다운로드·의존성 캐시, 설치본도 실행별로 그 아래에 두고 종료 전에 삭제합니다. 원격 QA 계정 생성, 시스템 로그인 항목 등록, 허용 경로 바깥에 쓰는 시험은 로컬이나 별도 시험 환경에서 수행합니다.

1. **시작할 때** 로컬 작업 기록에 원격 호스트와 실행 ID를 적습니다. 경로·계정·마운트·포트 포워딩을 만들거나 프로세스를 시작할 때마다 절대 경로, 계정 이름과 UID, 장치, PID 등 다시 식별할 값을 기록합니다. 기존 설정을 변경할 때는 원래 값도 기록합니다.
2. **결과를 회수할 때** 필요한 산출물과 시험 결과를 로컬에 복사하고 크기와 해시를 대조합니다. 정식판 설치본과 서명한 업데이트 자산도 원격 작업이 끝나기 전에 회수합니다.
3. **정리할 때** 이번 작업이 시작한 앱·백그라운드 프로세스·포트 포워딩을 종료합니다. 임시 마운트를 해제하고 로그인 항목 등 세션 설정을 원래 값으로 복원합니다. 기록과 대조해 시험용 계정과 홈, 앱, 다운로드, 임시 도구와 전용 의존성 캐시, 작업 복사본, 빌드 산출물을 삭제합니다. 공유 캐시를 쓰는 기존 도구는 보존하고, 새 캐시가 필요하면 실행별 임시 경로에 둡니다. 개발 설치본은 `npm run dev:delivery -- clean <installer.json>`으로 해시를 확인해 삭제할 수 있습니다.
4. **접속을 끊기 전** 기록한 경로와 계정, 실행 중인 프로세스, 열린 포워딩, 마운트와 변경한 설정을 원격에서 다시 조회합니다. 로컬 기록에 확인 결과를 남깁니다. 권한 등의 이유로 남은 자원이 있으면 정확한 대상과 이유를 사용자에게 알립니다.
