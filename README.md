# Sync Vault

Windows 11 x64와 Apple Silicon Mac 사이에서 클립보드와 파일을 공유하는 개인 LAN 앱입니다. 각 컴퓨터에 따로 설치하고 업데이트합니다.

[개발 설치본 전달과 E2E 검증](docs/e2e.md) · [성능 측정과 20분 상주 기준](docs/performance.md)

## 설치 파일

아래 개발·패키징 절차로 빌드하면 로컬 `release/` 폴더에 Windows x64용 `SyncVault-0.1.1-win-x64.exe` 또는 Apple Silicon Mac용 `SyncVault-0.1.1-mac-arm64.dmg`가 생성됩니다. 설치 파일의 SHA-256은 [실기기 검증 결과](VERIFICATION.md)에서 확인할 수 있습니다.

M4 Mac mini에도 `~/SyncVault-0.1.1/`에 DMG와 `feed/`를 준비했습니다. Finder에서 **이동 → 폴더로 이동**으로 이 경로를 열 수 있습니다.

## 처음 연결

1. Windows에서는 `SyncVault-…-win-x64.exe`를 실행합니다. Mac에서는 `.dmg`를 열고 **Sync Vault**를 응용 프로그램 폴더로 옮긴 뒤 실행합니다. 개인 배포본의 서명 상태는 검증 기록에서 확인하세요.
2. 같은 공유기의 Wi-Fi 또는 유선에 연결하고 양쪽 앱을 엽니다. 주변 목록은 mDNS와 선택한 IPv4 서브넷의 Sync Vault 탐색 메시지(UDP 49433)로 채웁니다. **기기 → 주변 기기 → 등록**을 누르고 두 화면의 확인값이 같은지 확인한 뒤 승인합니다. Windows 두 대와 Mac 한 대라면 각 기기 쌍을 한 번씩 등록합니다.
3. 자동 검색이 어려우면 왼쪽 아래 표시된 상대의 IP와 포트를 **주소로 직접 연결**에 입력합니다. 사용할 네트워크는 **설정**에서 바꿀 수 있습니다. Windows 개인 네트워크 방화벽 또는 Mac 로컬 네트워크 권한을 확인하세요. 한쪽에서만 연결을 열 수 있으면 등록된 상대가 먼저 연 연결을 활용합니다. 게스트망이 양쪽 통신을 모두 차단하면 서로 도달 가능한 LAN이 필요합니다.

## 클립보드와 파일

텍스트·표·링크·스크린샷을 복사한 후 상대 앱에서 붙여넣습니다. 파일 사진과 그림 자체는 다른 종류입니다. 여러 원본 사진은 탐색기 또는 Finder에서 함께 선택해 복사합니다. 기본 자동 전송 한도는 합계 32 MiB와 100개입니다. GIF 애니메이션·레이어·원본 메타데이터는 원본 파일로 보내세요.

| 복사 대상 | 0.1.1의 동작 범위 |
| --- | --- |
| 텍스트·URL·HTML | 한글·이모지·탭·여러 줄을 전달합니다. 기본 글자 서식, 표, 웹 링크를 허용하며 복사할 때 텍스트·HTML 표현당 최대 2 MiB를 읽습니다. |
| 이미지 한 장 | PNG로 전달하며 투명도를 유지합니다. PNG 한 장의 한도는 32 MiB이며 최대 픽셀 수는 50,331,648개입니다. |
| 이미지 여러 장 | 원본 앱이 각각의 이미지를 제공하면 PNG 파일 목록으로 전달합니다. Finder·탐색기에서 복사한 여러 사진은 원본 파일 목록으로 공유합니다. |
| 파일·폴더 | 한 작업은 하위 폴더를 포함해 최대 8,000개 항목입니다. 기본 자동 한도를 넘는 파일과 폴더는 받을 기기를 직접 선택합니다. 양쪽 OS에서 사용할 수 있는 이름이 필요하며 심볼릭 링크·정션은 제외합니다. |

큰 파일이나 폴더는 **전송**에 끌어놓고 받을 기기를 선택합니다. 수신자는 전송 목록에서 승인합니다. 기기별로 자동 수락을 켤 수 있습니다. 수신기는 파일을 디스크에 기록한 지점부터 이어받고 SHA-256이 일치하면 저장 폴더에 게시합니다. 같은 이름은 번호를 붙입니다. 완료된 작업에서 실제 저장 위치를 열 수 있습니다.

창을 닫으면 트레이·메뉴 막대에서 계속 동작합니다. 트레이에서 자동 공유를 일시 중지하거나 클립보드 그림을 PNG로 저장할 수 있습니다. 잠금 상태와 민감 표시 항목은 자동 전송에서 제외합니다. 앱이 비밀 표시를 제공하지 않는 일반 텍스트는 다른 텍스트처럼 전달됩니다.

현재 개발판은 로그인 자동 실행 시 창을 숨기고 직접 실행하면 창을 엽니다. 창이 닫혀 있을 때 기기 등록·수동 수신 요청이 오면 알림이나 트레이의 대기 요청을 눌러 확인할 수 있습니다. `Sync Vault Dev`는 독립된 설정과 등록 목록을 사용하며 첫 실행 때 공유가 일시 중지됩니다.

## 집 안에서 개별 업데이트

**설정 → 이 기기를 사설 배포처로 사용 → 배포 폴더 선택**에서 `update.json`, `update.sig`, 플랫폼별 ZIP이 있는 폴더를 선택합니다. 배포 기기도 같은 폴더에서 자기 업데이트를 확인할 수 있습니다. 등록된 상대에게만 서명된 목록에 포함된 패키지를 제공합니다. 배포 기기가 꺼져 있어도 설치된 버전에서 공유는 계속됩니다. 각 기기에서 **지금 확인 → 다운로드 → 전송 완료 후 설치** 또는 **지금 재시작**을 선택합니다.

## 개발·패키징

Node.js, npm, Windows의 Visual Studio C++ Build Tools 또는 Mac의 Xcode Command Line Tools가 필요합니다.

```sh
npm ci
npm test
npm run build
npm start
```

Windows에서 `npm run dist:win`, Apple Silicon Mac에서 `npm run dist:mac`을 실행합니다. 각 OS의 설치본과 업데이트 ZIP은 `release/`에 생성됩니다. 제품 식별자 및 릴리스 검증 공개키를 유지해야 기존 설치본이 새 릴리스를 신뢰합니다.

### 새 사설 릴리스 만들기

- 이 사본의 릴리스 검증 공개키는 `release-key.pub`입니다. Windows 서명 개인키는 발급한 Windows 계정의 DPAPI로 암호화해 무시된 `.release-keys/`에 보관합니다. 개인키 폴더는 배포처·설치본·다른 기기에 복사하지 않습니다. 별도의 배포 체계를 처음 만들 때만 `node scripts/release.mjs init`으로 자체 키를 발급합니다.
- 버전을 올려 두 OS에서 같은 공개키로 빌드하고, 두 ZIP을 서명 컴퓨터의 한 폴더에 모읍니다. 미리 만들어진 Ed25519 개인키를 사용할 때는 `SYNC_VAULT_SIGNING_FILE`로 경로를 지정할 수 있습니다.
- 다음 형식으로 **로컬** 배포 폴더를 준비합니다. 예시의 버전과 파일명은 실제 릴리스와 일치해야 합니다.

```sh
node scripts/release.mjs publish release/feed-0.1.1 0.1.1 release/SyncVault-0.1.1-win32-x64.zip release/SyncVault-0.1.1-darwin-arm64.zip
```

## 검증

`npm test`는 격리된 세 개의 TLS 피어, 등록 해제, 파일 중단 복구 및 서명된 사설 배포 폴더를 검증합니다. `npm run test:e2e`는 임시 프로필을 사용해 재실행과 설정 보존, 두 앱 간 등록·승인·취소, 저장 위치 분리 후 복구를 검증합니다. Mac에서는 시험 디스크를 가득 채운 뒤 재시도도 확인합니다. 빌드 후 `node tests/native.mjs`는 개인 클립보드와 분리된 OS 클립보드에 다중 파일을 기록합니다. `npm test` 후 `node artifacts/test/large.cjs`는 11 GiB 이상의 여유 공간에서 5 GiB TLS 전송을 절반 지점에서 중단·복구하고 해시를 비교합니다.
